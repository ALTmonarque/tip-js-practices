## Что реализовано

| Файл | Что сделано |
|---|---|
| `data.js` | `demoTasks` (общий набор из 4 задач) и `variantTasks` варианта 5: id 11, 23, 37, 41, 58, 64; первые четыре выполнены (начальный прогресс 66.7%). |

| `task-selectors.js` | `getVisibleTasks`: фильтры `all`, `pending`, `completed`. |
| `task-view.js` | Карточка с тремя действиями (`toggle`, `edit`, `delete`), список, сводка, пустое состояние. Названия выводятся через `textContent`. |
| `form-validation.js` | Чистая `validateTaskDraft`: id (создание/редактирование), название после `trim()`, приоритет; ошибки по полям. |
| `task-storage.js` | `isValidTaskList`, `loadTasks`, `saveTasks`, `removeSavedTasks`; запись `{ version: 1, tasks }`, объект `storage` передаётся аргументом. |
| `main.js` | `renderApp`, режимы формы (`setFormMode`), `handleFormSubmit`, делегирование кликов, фильтры, сброс. |

## Организация кода

- `task-service.js` — правила модели и операции, возвращающие `{ ok, ... }`; без DOM и `localStorage`.
- `form-validation.js` — первый уровень: нормализация и проверка ввода формы, без показа ошибок.
- `task-storage.js` — единственное место, где задействованы JSON и `localStorage`. Функции получают `storage` аргументом, поэтому проверяются на объекте-имитации. Данные из JSON проверяются до использования, потому что JSON не гарантирует корректность схемы.
- `task-view.js` — только создание DOM; `main.js` — состояние, события и координация модулей.
